Suggestions & decision path

A dedicated place to review suggestions and choose a path before implementing any change. It lists the decision options, the conditions that must be true before any option is lawful, the questions whose answers are still missing, site-improvement suggestions, and a review protocol. Re-checked against the official sources on 13 November 2026; the canonical research pass is 11 November 2026. Decision support, not legal advice.

How to use it: nothing here decides the increase for you. Work top to bottom — confirm the preconditions (B), answer the open questions (C), weigh the options (A) against the tenant-lawyer test (review page), and only then implement.

D. Suggestions to improve the site and decision-making

Proposals for the site itself, not verified facts. Each one is a suggested improvement for a reviewer to accept, reject or amend before it is implemented.

  • Add a printable “serve a notice” checklist that walks through preconditions → calculation → notice → service → any filing, linked to the licence & process page.
  • Add a per-unit “next action” panel showing the earliest lawful effective date and the latest notice-service date for each unit, recomputed from the official percentages.
  • Add a source-freshness indicator on every page showing the last retrieval date and whether any cited official source has since been updated.
  • Add a plain-language glossary for “banked increase”, “anniversary date”, “licence”, “coverage” and “base rent”, each defined from the linked official source.
  • Add a decision-record template so a reviewer can record which option was chosen, the evidence relied on, and the date — creating an audit trail before implementation.
  • Add a cross-unit comparison view so the one-unit-vs-both decision can be reviewed side by side against the fair-housing analysis on the discrimination page.

E. Review protocol — how to choose the best path

  1. Resolve the preconditions (B) for each unit. A missing licence, wrong anniversary, wrong base rent or wrong notice period defeats the increase regardless of the percentage chosen. sf.gov — The Rent Board Housing Inventory · Cal. Civ. Code § 827 — notice to change terms of tenancy
  2. Answer the open questions (C) and attach the evidence. The Unit B ledger, building record, coverage, licence status and subsidy status are the facts that change the outcome. sf.gov — Banked rent increases · sf.gov — Learn about San Francisco rental laws
  3. Compare the options (A) against the tenant-lawyer test. Run the chosen option through the 16-point review on the tenant-lawyer test page before committing.
  4. Record the decision. Use the decision-record template (D) to note the option, the evidence and the date, so the choice can be reviewed later.
  5. Only then implement. Confirm the licence, calculate from the percentage in force on the effective date, serve notice in time, and file anything the Rent Board requires. sf.gov — Learn about rent increases in San Francisco · sfgov.legistar.com — File #261020, cap on rent increases for rent-controlled units

How to respond

Reply with the IDs and a word — “S-03 adopt, S-10 decline, S-01 adopt with change: 90-day threshold”. Anything not marked stays proposed. No suggestion is implemented on the strength of being reasonable; the record of what was chosen and by when will sit on this page.

What will not be proposed or implemented here: client-side scripts (the site is static by design and its build gate rejects them), any figure not published by an official source, any change to dates or amounts, and any tenant-identifying detail. That is why this page has no search box, no calculator and no market-rent estimate — and why the values the official sources do not publish are left blank on every other page instead of filled in.

Standing constraints any accepted suggestion must respect

  • Generate, never hand-edit. Pages are built from the modules in tools/; the CI job fails if the committed HTML differs from a fresh build.
  • Every data row keeps an official link or is blank and flagged — this page follows the same rule.
  • Nothing is deleted. Earlier editions stay online, which is why S-14 is a labelling exercise rather than a cleanup.
  • Anonymisation is not relaxed for convenience: placeholders stay, and the withheld address, ZIP and neighbourhood stay withheld.
  • Dates and dollar amounts are not adjusted by a site change; the instruction is explicit and the arithmetic assertions in the build enforce it.
  • Pending law stays pending — File No. 261020 is described by its Legistar status, never as a rule to plan on.
